# Vercel Deployment Policy

The project uses Vercel's project-level **Ignored Build Step** preset:

**Only build production**

Configured at:

`Project Settings → Build and Deployment → Ignored Build Step`

The gray command shown in the Vercel dashboard is generated by the preset and is not custom editable Bash. Do not replace it with a hand-written `bash if ...` command.

## Verified behavior

After enabling the preset, multiple new commits pushed to `release/v1.3` created **no Vercel deployment records**. This confirms preview/release-branch builds are being skipped.

## Release flow

1. Develop on a branch such as `release/v1.3`.
2. Open and review the pull request without a Vercel preview build.
3. Squash-merge the approved PR into `main`.
4. The resulting production/main commit triggers the production deployment.
5. Verify the production URL, `/import`, `/methodology`, and any serverless endpoints.

`vercel.json` does not contain a competing Git deployment gate.
